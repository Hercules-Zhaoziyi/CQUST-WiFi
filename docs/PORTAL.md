# 信息门户与统一登录

四种用途分别为校园网、课表、信息门户、全部。门户不依赖上网服务开通，也不以课表同步成功作为前提。

## Windows

`portalSignIn` 复用 CAS 协议，把校方返回的 WebVPN token-login 或带 ST 的 CAS 网关回调交给系统默认浏览器。支持网关包装后的回调路径；交接前不消费这张一次性票据。

校验精确域名、HTTPS、443 端口、路径与查询参数。认证票据只交给校方地址，不向前端返回、不写日志，不导出 Cookie，不把账号密码拼入 URL。没有收到有效交接地址时明确失败。

默认浏览器接收地址不等于已证实页面登录成功；实际效果仍需真实校园账号验证。学校验证码、二次认证和服务策略保留。

## Android

优先使用 Chrome Custom Tabs，在真实浏览器中完成一次性票据交接，导航完成后打开所选服务。未安装 Chrome 或绑定失败时交给默认浏览器。既有独立 WebView 只保留为已获得应用内有效会话时的兼容入口。

凭据只按用户记住密码选项保存，签名私钥仅本机保管。浏览器打开成功不等于业务系统认证成功。

## 服务入口

两端使用同一份已核对的菜单路径：科研、学工、实践教学、毕业论文、邮件、课程中心、心理健康、运维中心、学生收费、软件正版化。路径仅包含校方公开服务标识，不包含用户身份或会话。教务与实践教学优先使用各自 SSO 入口；尚未核对的服务回到门户菜单，不猜测地址。

Windows 完成首次交接后可从卡片再次进入服务；短时复用只记录最近打开时间，不宣称浏览器一定已登录。2026-11-12 核对时科研系统直接访问返回 HTTP 502，业务端可用性仍需校方恢复或其网关正常转发。
