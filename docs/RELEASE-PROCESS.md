# 双端发布流程

今后的软件更新必须同时发布到 GitHub 与 Gitee，不能把“候选代码测试通过”当成“软件已发布”。

1. 先修复软件，递增桌面与安卓版本号、安卓 versionCode，执行单元、界面与升级回归。学校真实账号验证与隔离测试必须区分。
2. 安卓签名私钥、密码仅在本机保管，不进入仓库、Releases 或 Actions Secrets。
3. 先发布 GitHub 新安装包、对应源码与 SHA-256 清单，确认公开状态和附件哈希，先向用户提供可安装的新版。
4. 随后同步 Gitee 源码和新版本附件。只有确认 Gitee 无独立提交时才能同步；不得默认删除额外分支、标签或覆盖 Wiki。不迁移全部旧版附件。
5. 匿名下载 Gitee 新安装包核对与 GitHub、本机的 SHA-256 一致，不能只看上传卡片或发布标题。
6. 核验后更新 `updates/windows.json`、`updates/android.json`：Gitee 主源，GitHub 备用；安装包的大小、哈希、版本和链接必须对应同一文件。
7. 最后更新宣传页源码与静态包，上传两端。用户此前要求源码交付，不默认部署网站。

无独立地址的校园服务必须明确进入门户菜单，不编造业务 URL；获得入口地址不等于已验证其业务会话，学校权限、验证码和二次认证均由校方执行。

## GitHub 自动镜像

2026-11-13 已配置 GitHub → Gitee 的 Pull 自动镜像，使用 push Webhook 触发。源码、分支和标签由镜像同步；Releases 安装包和网页交付附件仍需按上述流程单独上传并核验。不要把安卓签名私钥或密码交给镜像、仓库或 CI。
