# Android 发布签名

从 1.0.0-beta02 起使用固定 RSA 3072 发布证书，本机签名。GitHub Actions 仅构建无签名 release APK，不保管签名私钥或其密码。发布附件只包含签名后的 APK、源码和校验值。

发布证书 SHA-256：

```text
d5a3b617cb411a841391b8344accf6440810282609020d1167d6f2a579f89248
```

1.0.0-beta01 使用旧 debug 签名，不能直接覆盖更新到发布签名版本。需要用户自行确认卸载重装，旧版私有数据会清除；应用不会自动卸载、降级或清空数据。1.0.0-beta02 和 1.1.0-beta01 可直接覆盖更新到 1.1.0-beta02，保留原数据。

v1、v2、v3 分别按对应 Android SDK 区间验证。默认验证输出可能只报告当前 SDK 使用的最强方案，不能把未采用的方案显示为 false 解读为“没有此签名”。安装回归使用同一本机签名 APK 的只读测试对象，并校验完整 SHA-256；CI 仍不持有发布私钥。

之后的发布包保持相同签名；更新模块校验应用标识、递增版本号、GitHub 资产 SHA-256、文件长度及签名一致性，再调用系统安装界面。安装仍需用户同意。不可把无签名 CI 产物或随机 debug 签名的测试 APK 当作正式发布附件。

维护者应妥善保管离线签名备份。私钥及密码不得进入 Git 仓库、公开文件、Releases、日志或 CI Artifacts。
